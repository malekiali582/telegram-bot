# راه‌اندازی «لولو» روی سرور، قدم‌به‌قدم

این راهنما برای کسی است که **تا حالا با سرور لینوکس کار نکرده**. از خرید سرور شروع می‌کند و به این‌جا می‌رسد:

- ربات در تلگرام جواب می‌دهد؛
- پنل مدیریت با `https://` باز می‌شود؛
- هر شب خودکار از دیتابیس بکاپ گرفته می‌شود.

همه‌چیز روی یک سرور مجازی (VPS) با **اوبونتو ۲۴.۰۴** و **۴ گیگ رم** اجرا می‌شود: ربات، worker، API، پنل و PostgreSQL. وقت لازم حدود یک تا دو ساعت است؛ بیشترش انتظار برای نصب است.

> **مهم پیش از شروع:** با هر توکن ربات فقط یک جا می‌شود ربات را روشن داشت. اگر ربات الان روی کامپیوتر دیگری روشن است، در **قدم ۱۳** خاموشش می‌کنید. تا آن موقع به آن دست نزنید.

## چطور این راهنما را دنبال کنید

- **بلوک‌های دستور:** هر بلوک خاکستری یک یا چند دستور است. کل بلوک را کپی کنید، در پنجرهٔ سرور بچسبانید و Enter بزنید. چسباندن در PowerShell: کلیک راست یا `Ctrl + V`.
- **جاهای خالی:** چیزهایی که داخل `< >` آمده‌اند را با مقدار خودتان عوض کنید و خود `< >` را پاک کنید. مثلاً `<IP سرور>` می‌شود `203.0.113.10`.
- **پایان هر دستور:** وقتی دستور تمام شود، دوباره خطی مثل `root@lulu:~#` ظاهر می‌شود. تا آن نیامده، دستور بعدی را نزنید.
- **وقتی چیزی غیرمنتظره دیدید:** همان‌جا بایستید. متن خطا را کپی کنید و از بخش «اگر چیزی درست کار نکرد» (آخر همین راهنما) یا از کسی کمک بگیرید. ادامه دادن با خطا معمولاً کار را سخت‌تر می‌کند.

## ۰. فهرست چیزهایی که لازم دارید

- [ ] **توکن ربات** از [@BotFather](https://t.me/BotFather): در BotFather بنویسید `/mybots`، ربات را انتخاب کنید و «API Token» را بزنید.
- [ ] **دسترسی به کد پروژه در GitHub:** آدرس مخزن، و اگر مخزن خصوصی است یک توکن دسترسی (قدم ۶).
- [ ] **یک سرور مجازی** (قدم ۱).
- [ ] **یک دامنه** (قدم ۲)، مثلاً `example.com`. پنل و ربات روی یک زیردامنه‌اش می‌آیند، مثلاً `lulu.example.com`.
- [ ] **یک کامپیوتر ویندوزی** با PowerShell. در ویندوز ۱۰ و ۱۱ از قبل هست: منوی Start ← بنویسید PowerShell.
- [ ] **جایی امن برای یادداشت رمزها**، مثل یک برنامهٔ مدیریت رمز.

## ۱. خرید سرور

از یک شرکت ارائهٔ VPS، مثلاً Hetzner، DigitalOcean یا Vultr، یک سرور با این مشخصات بخرید:

| مورد       | مقدار                                          |
| ---------- | ---------------------------------------------- |
| سیستم‌عامل | **Ubuntu 24.04 LTS**                           |
| رم         | ۴ گیگابایت                                     |
| پردازنده   | ۲ هسته (vCPU)                                  |
| دیسک       | دست‌کم ۴۰ گیگابایت SSD                         |
| آدرس       | IPv4 عمومی (معمولاً خودکار هست)                |
| محل سرور   | **خارج از ایران**، مثلاً آلمان، هلند یا فنلاند |

- **محل سرور:** تلگرام در ایران فیلتر است و سروری که داخل ایران باشد به سرورهای تلگرام وصل نمی‌شود. پس سرور حتماً باید بیرون از ایران باشد.
- **روش ورود:** اگر هنگام ساخت سرور بین «رمز» (Password) و «کلید SSH» حق انتخاب داشتید، برای شروع «رمز» ساده‌تر است. بعداً می‌توانید کلید بگذارید (قدم ۱۷).

بعد از ساخته شدن سرور، این دو را یادداشت کنید:

- **آدرس IP سرور**، مثلاً `203.0.113.10`؛
- **رمز کاربر `root`**، که یا خودتان گذاشته‌اید یا به ایمیلتان فرستاده شده.

## ۲. دامنه و DNS

پنل و ربات باید روی یک نام دامنه باشند؛ گواهی HTTPS فقط برای نام دامنه صادر می‌شود، نه برای IP.

1. **دامنه را بخرید:** اگر دامنه ندارید، از یک ثبت‌کنندهٔ دامنه (مثلاً Namecheap یا Cloudflare) بخرید. دامنهٔ بین‌المللی مثل `.com` یا `.net` مطمئن‌تر است؛ گرفتن گواهی برای بعضی دامنه‌های کشوری ممکن است مشکل داشته باشد.
2. **رکورد A بسازید:** در تنظیمات DNS دامنه یک رکورد تازه اضافه کنید:

   | نوع (Type) | نام (Name/Host) | مقدار (Value/Points to) | TTL    |
   | ---------- | --------------- | ----------------------- | ------ |
   | `A`        | `lulu`          | `<IP سرور>`             | خودکار |

   این کار `lulu.example.com` را به سرور شما وصل می‌کند. اگر DNS دامنه دست Cloudflare است، ابر نارنجی (Proxy) را خاموش کنید تا خاکستری شود (DNS only).

3. **بررسی کنید.** چند دقیقه صبر کنید و در PowerShell بزنید:

   ```powershell
   nslookup lulu.example.com
   ```

   در خروجی باید IP سرورتان را ببینید. اگر نمی‌بینید، کمی بیشتر صبر کنید؛ گاهی تا یک ساعت طول می‌کشد.

از اینجا به بعد هر جا `lulu.example.com` آمده، دامنهٔ خودتان را بگذارید.

## ۳. وصل شدن به سرور

در PowerShell بنویسید (IP را عوض کنید):

```powershell
ssh root@<IP سرور>
```

- **بار اول:** سؤالی دربارهٔ `fingerprint` می‌آید. بنویسید `yes` و Enter بزنید.
- **رمز:** رمز `root` را بنویسید و Enter بزنید. **موقع تایپ رمز هیچ چیزی نشان داده نمی‌شود**؛ عادی است.
- **ورود موفق:** خطی مثل `root@lulu:~#` می‌آید. حالا هر دستوری بزنید روی سرور اجرا می‌شود، نه روی کامپیوتر خودتان.
- **خروج و ورود دوباره:** با دستور `exit` خارج می‌شوید. هر بار که خواستید برگردید، همین `ssh root@<IP سرور>` را بزنید.

**رمز `root` را عوض کنید.** رمزی که شرکت فرستاده ممکن است جای دیگری هم ذخیره شده باشد:

```
passwd
```

رمز تازه را دو بار بنویسید (باز هم دیده نمی‌شود) و یادداشتش کنید.

## ۴. آماده کردن سیستم

### ۴-۱. به‌روزرسانی

```
sudo apt-get update && sudo NEEDRESTART_MODE=a apt-get upgrade -y
```

- چند دقیقه طول می‌کشد.
- اگر صفحهٔ بنفشی با سؤال آمد، Enter بزنید تا گزینهٔ پیش‌فرض انتخاب شود.

بعد سرور را یک بار ری‌استارت کنید:

```
sudo reboot
```

اتصال قطع می‌شود. یک دقیقه صبر کنید و دوباره وصل شوید (`ssh root@<IP سرور>`).

### ۴-۲. فضای swap

swap حافظهٔ کمکی روی دیسک است. سرور ۴ گیگی برای نصب و ساخت پروژه با آن مطمئن‌تر است:

```
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

در خروجی `free -h`، ردیف `Swap` باید حدود `2.0Gi` باشد.

### ۴-۳. فایروال

فایروال فقط سه درگاه را باز می‌گذارد:

- SSH، برای وصل شدن خودتان؛
- ۸۰ و ۴۴۳، برای HTTPS.

```
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable
sudo ufw status
```

در خروجی باید `Status: active` و این سه قاعده را ببینید.

> ساعت سرور را عوض نکنید؛ بگذارید UTC بماند. بازی خودش همه‌چیز را به وقت تهران حساب می‌کند.

## ۶. کاربر جدا و دریافت کد

برنامه‌ها با یک کاربر جدا به نام `lulu` اجرا می‌شوند، نه با `root`. این‌طور اگر یک روز مشکلی پیش بیاید، به کل سرور نمی‌رسد.

```
sudo useradd --create-home --shell /bin/bash lulu
sudo mkdir -p /srv/lulu
sudo chown lulu:lulu /srv/lulu
```

### اگر مخزن GitHub خصوصی است: ساخت توکن

مخزن عمومی این بخش را لازم ندارد. برای مخزن خصوصی، GitHub به‌جای رمز یک «توکن دسترسی» می‌خواهد:

1. در GitHub بروید به: عکس پروفایل ← **Settings** ← پایین صفحه **Developer settings** ← **Personal access tokens** ← **Fine-grained tokens** ← **Generate new token**.
2. یک نام بدهید (مثلاً `lulu-server`) و مدت اعتبار را انتخاب کنید.
3. در **Repository access** گزینهٔ **Only select repositories** را بزنید و فقط همین مخزن را انتخاب کنید.
4. در **Permissions** ← **Repository permissions** ← **Contents** را روی **Read-only** بگذارید.
5. **Generate token** را بزنید و توکن را کپی و یادداشت کنید. فقط همین یک بار نشان داده می‌شود.

این دستور باعث می‌شود سرور توکن را بعد از بار اول به خاطر بسپارد، تا موقع به‌روزرسانی دوباره نپرسد:

```
sudo -u lulu -H git config --global credential.helper store
```

### دریافت کد

آدرس مخزن خودتان را بگذارید:

```
sudo -u lulu -H git clone https://github.com/<نام کاربری>/<نام مخزن>.git /srv/lulu
cd /srv/lulu
```

اگر مخزن خصوصی باشد، دو چیز می‌پرسد:

- `Username`: نام کاربری GitHub؛
- `Password`: **توکنی که ساختید**، نه رمز GitHub. موقع چسباندن دیده نمی‌شود.

> **از اینجا به بعد** همهٔ دستورها را داخل پوشهٔ `/srv/lulu` بزنید. اگر اتصال قطع شد و دوباره وصل شدید، اول `cd /srv/lulu` را بزنید.

## ۷. ساختن فایل تنظیمات (`.env`)

یک اسکریپت آماده سه چیز از شما می‌پرسد. بقیهٔ رمزها، مثل رمز دیتابیس و کلیدهای امنیتی، را خودش به‌صورت تصادفی می‌سازد:

```
cd /srv/lulu
sudo -u lulu bash deploy/make-env.sh
```

پرسش‌ها:

1. **دامنه:** مثلاً `lulu.example.com`، بدون `https://`.
2. **توکن ربات:** از BotFather. موقع چسباندن دیده نمی‌شود؛ بعدش Enter بزنید.
3. **نام کاربری مالک پنل:** حروف کوچک انگلیسی، مثلاً `owner`.
4. **رمز مالک پنل:** دست‌کم ۱۲ نویسه. اگر خالی بگذارید و Enter بزنید، یک رمز تصادفی ساخته و نشان داده می‌شود. **همان لحظه یادداشتش کنید.**

در آخر پیام `✅ .env ساخته شد` می‌آید.

> فایل `.env` همهٔ رمزهاست. آن را برای کسی نفرستید، در جایی کپی نکنید و در GitHub نگذارید.

## ۸. روشن کردن دیتابیس

```
cd /srv/lulu
sudo docker compose up -d
```

- بار اول چند دقیقه طول می‌کشد تا PostgreSQL دانلود شود.
- بعد از حدود ۳۰ ثانیه وضعیت را ببینید:

  ```
  sudo docker compose ps
  ```

  در ستون `STATUS` باید `healthy` ببینید.

- اگر `starting` است، کمی صبر کنید و دوباره بزنید.

## ۹. نصب و ساختن پروژه

```
cd /srv/lulu
sudo -u lulu -H npm ci
sudo -u lulu -H npm run build
```

- هر کدام چند دقیقه طول می‌کشد.
- **هشدارها:** در آخر `npm ci` ممکن است چند هشدار (`warn`) ببینید؛ مهم نیست. در `build` هم هشداری دربارهٔ `chunks are larger than 500 kB` عادی است.
- **خطا:** فقط اگر کلمهٔ `ERR!` یا `error` و توقف کامل دیدید، ادامه ندهید.

> **دادهٔ ربات فعلی را می‌خواهید؟** اگر ربات تا حالا روی کامپیوتر دیگری با `npm run dev` کار می‌کرده و می‌خواهید بازیکن‌ها و امتیازهایشان به سرور بیایند، **همین حالا**، پیش از قدم ۱۰، بخش ۷ از `docs/operations.md` را انجام دهید. اگر از صفر شروع می‌کنید، این را رد کنید.

## ۱۰. ساختن حساب مالک پنل

```
cd /srv/lulu
sudo -u lulu -H npm run admin:bootstrap
```

باید پیام `✅ حساب مالک «owner» ساخته شد` را ببینید.

حالا نام کاربری و رمز اولیه را از `.env` پاک کنید. دیگر لازم نیستند و بهتر است روی دیسک نمانند:

```
sudo -u lulu sed -i '/^ADMIN_BOOTSTRAP_/d' /srv/lulu/.env
```

## ۱۱. HTTPS با Caddy

فایل تنظیم Caddy را بگذارید. دامنه خودکار از `.env` خوانده می‌شود:

```
DOMAIN=$(sudo grep '^PUBLIC_BASE_URL=' /srv/lulu/.env | cut -d/ -f3)
echo "دامنه: $DOMAIN"
sudo cp /srv/lulu/deploy/Caddyfile /etc/caddy/Caddyfile
sudo sed -i "s/lulu.example.com/$DOMAIN/" /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
```

- `echo` باید دامنهٔ شما را نشان دهد.
- `validate` باید با `Valid configuration` تمام شود.

**بررسی گرفتن گواهی:** چند ثانیه صبر کنید و بزنید:

```
sudo journalctl -u caddy -n 30 --no-pager | grep -i certificate
```

- **موفق:** باید `certificate obtained successfully` ببینید.
- **ناموفق:** معمولاً یعنی دامنه هنوز به IP سرور اشاره نمی‌کند (قدم ۲)، یا پورت ۸۰ یا ۴۴۳ بسته است (قدم ۴-۳).

## ۱۲. نصب سرویس‌ها

این فایل‌ها به سرور می‌گویند ربات، worker و API را چطور اجرا کند، و بعد از ری‌استارت سرور خودکار روشنشان کند:

```
sudo cp /srv/lulu/deploy/systemd/lulu-*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable lulu-api lulu-worker lulu-bot
```

هنوز روشنشان نکنید.

## ۱۳. خاموش کردن ربات روی کامپیوتر دیگر

اگر ربات با همین توکن جای دیگری روشن است، **همین حالا خاموشش کنید**. در پنجره‌ای که `npm run dev` در آن اجرا می‌شود، `Ctrl + C` را بزنید.

دو ربات با یک توکن نمی‌توانند هم‌زمان کار کنند. از این به بعد ربات فقط روی سرور اجرا می‌شود.

## ۱۴. روشن کردن و بررسی

```
sudo systemctl start lulu-api lulu-worker lulu-bot
sleep 10
systemctl status lulu-api lulu-worker lulu-bot --no-pager | grep -E '●|Active:'
```

هر سه سرویس باید `active (running)` باشند.

**بررسی‌ها:**

1. **سلامت API:**

   ```
   curl -s https://$(sudo grep '^PUBLIC_BASE_URL=' /srv/lulu/.env | cut -d/ -f3)/api/health
   ```

   باید `{"ok":true}` ببینید.

2. **webhook ربات:**

   ```
   sudo journalctl -u lulu-bot -n 30 --no-pager | grep -E 'webhook registered|privacy'
   ```

   - باید `telegram webhook registered` ببینید.
   - اگر خطی با `group privacy is ON` آمد: در BotFather بنویسید `/setprivacy`، ربات را انتخاب کنید و **Disable** را بزنید. بعد ربات را از گروه‌ها حذف کنید و دوباره اضافه کنید. بدون این کار، ربات در گروه‌هایی که ادمین نیست «لولو» را نمی‌بیند.

3. **پنل:** در مرورگر `https://lulu.example.com` را باز کنید و با نام کاربری و رمز قدم ۷ وارد شوید.
   - در صفحهٔ **«سیستم»** ربات و worker باید «روشن» باشند.
   - در **داشبورد** هشدار «بستهٔ روح ندارد» طبیعی است: از صفحهٔ **«محتوای روح»** برای شب‌های آینده بسته اضافه کنید.

4. **ربات:** در تلگرام به ربات پیام بدهید، یا در گروهی که ربات در آن است بنویسید `لولو`. باید جواب بدهد.

🎉 ربات و پنل روشن‌اند.

## ۱۵. بکاپ خودکار روزانه

### بکاپ شبانه روی خود سرور

این دستورها کاری تعریف می‌کنند که هر شب ساعت ۳ بامداد به وقت تهران (۲۳:۳۰ UTC) یک بکاپ کامل از دیتابیس بگیرد:

- بکاپ در `/var/backups/lulu` ذخیره می‌شود؛
- هر بکاپ بعد از ساخته شدن بررسی می‌شود که سالم و خواندنی باشد؛
- بکاپ‌های قدیمی‌تر از ۱۴ روز خودکار پاک می‌شوند.

```
sudo mkdir -p /var/backups/lulu && sudo chmod 700 /var/backups/lulu
echo '30 23 * * * root cd /srv/lulu && PG_BACKUP_DIR=/var/backups/lulu bash scripts/server/pg-backup.sh >> /var/log/lulu-backup.log 2>&1' | sudo tee /etc/cron.d/lulu-backup
```

یک بار همین حالا دستی اجرایش کنید تا مطمئن شوید کار می‌کند:

```
cd /srv/lulu && sudo PG_BACKUP_DIR=/var/backups/lulu bash scripts/server/pg-backup.sh
sudo ls -lh /var/backups/lulu
```

- باید `backup ok` و یک فایل `lulu-....dump` ببینید.
- از فردا هر روز گزارش را با این دستور ببینید:

  ```
  sudo tail /var/log/lulu-backup.log
  ```

### یک نسخه هم روی کامپیوتر خودتان

اگر سرور از دست برود، بکاپی که فقط روی خود سرور است هم از دست می‌رود. **دست‌کم هفته‌ای یک بار** بکاپ‌ها را به کامپیوتر خودتان بیاورید. در **PowerShell کامپیوتر خودتان** (نه روی سرور):

```powershell
mkdir $HOME\lulu-backups -Force
scp "root@<IP سرور>:/var/backups/lulu/*.dump" $HOME\lulu-backups\
```

فایل‌ها در پوشهٔ `lulu-backups` در پوشهٔ کاربری‌تان ذخیره می‌شوند. بکاپ همهٔ دادهٔ بازیکن‌ها را دارد؛ آن را جای امن نگه دارید.

**بازگردانی بکاپ:** در `docs/backup.md`، بخش ۲. در دستورهای آن بخش، مسیر فایل‌ها `/var/backups/lulu/...` است.

> **بکاپ از پنل:** مالک می‌تواند هر وقت خواست از صفحهٔ «سیستم» ← «گرفتن بکاپ» هم یک بکاپ بگیرد و دانلود کند؛ مثلاً پیش از تغییر بزرگ در تنظیمات اقتصاد.

## ۱۶. کارهای بعدی و روزمره

همهٔ دستورهای این بخش روی سرور است (`ssh root@<IP سرور>`).

| می‌خواهم…                                 | دستور                                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------------ |
| وضعیت سرویس‌ها را ببینم                   | `systemctl status lulu-bot lulu-worker lulu-api --no-pager`                    |
| لاگ ربات را زنده ببینم (خروج: `Ctrl + C`) | `sudo journalctl -u lulu-bot -f`                                               |
| سرویس‌ها را دوباره روشن کنم               | `sudo systemctl restart lulu-api lulu-worker lulu-bot`                         |
| نسخهٔ تازهٔ کد را نصب کنم                 | `sudo bash /srv/lulu/deploy/update.sh` (اول خودش بکاپ می‌گیرد)                 |
| رمز مالک پنل را فراموش کرده‌ام            | `cd /srv/lulu && sudo -u lulu -H npm run admin:reset-password -- <نام کاربری>` |
| ببینم دیسک چقدر پر است                    | `df -h /`                                                                      |
| سرور را ری‌استارت کنم                     | `sudo reboot` (همه‌چیز بعدش خودکار روشن می‌شود)                                |

- **ری‌استارت سرور:** بعد از ری‌استارت لازم نیست کاری بکنید. دیتابیس، Caddy، ربات، worker و API خودشان روشن می‌شوند.
- **به‌روزرسانی‌های امنیتی** اوبونتو خودکار نصب می‌شوند. ماهی یک بار هم این را بزنید:

  ```
  sudo apt-get update && sudo NEEDRESTART_MODE=a apt-get upgrade -y
  ```

- **تغییر تنظیمات:** اگر چیزی را در `.env` عوض کردید، سرویس‌ها را دوباره روشن کنید.

## ۱۷. (اختیاری، ولی توصیه‌شده) ورود با کلید SSH

ورود با کلید از رمز امن‌تر است و رمز `root` را از دسترس حمله‌های حدس رمز دور می‌کند.

1. **کلید بسازید.** در **PowerShell کامپیوتر خودتان**:

   ```powershell
   ssh-keygen -t ed25519
   ```

   سه بار Enter بزنید. یک رمز اختیاری برای خود کلید هم می‌پرسد.

2. **کلید را روی سرور بگذارید:**

   ```powershell
   type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@<IP سرور> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
   ```

   یک بار دیگر رمز `root` را می‌پرسد.

3. **امتحان کنید:** `exit` بزنید و دوباره `ssh root@<IP سرور>` را بزنید. اگر **بدون پرسیدن رمز سرور** وارد شدید، کلید کار می‌کند.

4. **فقط بعد از اینکه مطمئن شدید کلید کار می‌کند**، ورود با رمز را ببندید:

   ```
   echo 'PasswordAuthentication no' | sudo tee /etc/ssh/sshd_config.d/90-no-password.conf
   sudo systemctl reload ssh
   ```

   از این به بعد فقط از همین کامپیوتر می‌شود وارد شد. پوشهٔ `.ssh` آن را جایی امن نسخه بگیرید. اگر کلید گم شود، تنها راه ورود، کنسول وب شرکت ارائهٔ سرور است.
