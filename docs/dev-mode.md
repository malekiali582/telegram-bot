# اجرای «لولو» روی سیستم خودتان (حالت توسعه)

این راهنما برای اجرای ربات با یک **ربات تستی** روی کامپیوتر خودتان است: بدون Docker و بدون سرور. دیتابیس PostgreSQL واقعی به‌صورت خودکار کنار پروژه اجرا می‌شود.

> این حالت فقط برای آزمایش است. راه‌اندازی روی سرور واقعی (webhook و HTTPS) در `docs/operations.md` می‌آید.

## پیش‌نیازها

- **Node.js نسخهٔ ۲۲** (با `node --version` بررسی کنید).
- **اتصال به تلگرام از خود کامپیوتر:** اگر از فیلترشکن استفاده می‌کنید، باید در حالت «کل سیستم» (System/TUN) باشد. تنظیم پراکسیِ مرورگر روی Node اثری ندارد.
- **یک حساب تلگرام** برای ساختن ربات تستی. برای چند تست، حساب دوم (مثلاً روی گوشی دیگر) مفید است.

## گام ۱: ساختن ربات تستی در BotFather

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید و `/newbot` را بفرستید.
2. یک نام (مثلاً «لولوی تستی من») و یک username که به `bot` ختم شود (مثلاً `my_lulu_test_bot`) بدهید.
3. BotFather یک **توکن** به این شکل می‌دهد: `123456789:AAH...`. آن را کپی کنید و به هیچ‌کس ندهید.
4. **Privacy Mode را خاموش کنید** تا ربات پیام سادهٔ «لولو» را در گروه ببیند:
   - به BotFather بفرستید: `/setprivacy`
   - ربات را انتخاب کنید.
   - گزینهٔ `Disable` را بزنید.
   - اگر ربات قبلاً در گروهی بوده، یک بار از گروه حذف و دوباره اضافه‌اش کنید تا تغییر اثر کند.

## گام ۲: گذاشتن توکن

1. در پوشهٔ اصلی پروژه (`LULU Bot`) فایل `.env.example` را کپی کنید و اسم کپی را `.env` بگذارید.
2. `.env` را باز کنید و خط زیر را با توکن خودتان پر کنید:

   ```
   TELEGRAM_BOT_TOKEN=123456789:AAH...
   ```

بقیهٔ خطوط برای حالت توسعه لازم نیست. فایل `.env` در git ثبت نمی‌شود.

## گام ۳: اجرا

در ترمینالِ پوشهٔ پروژه (مثلاً ترمینال VS Code):

```
npm install
npm run dev
```

`npm install` فقط بار اول (یا بعد از به‌روزرسانی پروژه) لازم است.

اجرای اول حدود ۱۰ ثانیه طول می‌کشد، چون دیتابیس ساخته می‌شود. اگر همه‌چیز درست باشد، در ترمینال این را می‌بینید:

```
✅ ربات @my_lulu_test_bot روشن است (حالت توسعه، long polling).
   دیتابیس: PostgreSQL محلی در ...\LULU Bot\.lulu-dev — پورت 54329
```

- **خاموش کردن:** `Ctrl + C` را بزنید. داده‌ها در پوشهٔ `.lulu-dev` می‌مانند و اجرای بعدی از همان‌جا ادامه می‌دهد.
- **شروع از صفر:** ربات را خاموش کنید و پوشهٔ `.lulu-dev` را پاک کنید.

## گام ۴: آیا درست کار می‌کند؟

1. به ربات در گفت‌وگوی خصوصی `/start` بدهید. باید پیام خوش‌آمد با دکمه‌های «افزودن به گروه»، «راهنما» و «غار من» برسد.
2. ربات را به یک گروه تستی اضافه کنید. باید پیام «این گروه حالا یک لولوآباد است» برسد.
3. در گروه بنویسید `لولو`. باید چیزی شبیه «🧛 فلانی لولو کرد: +۳ پوینت» برسد.

**اگر جوابی نیامد:**

1. ترمینال را نگاه کنید. خطاها با `WARN`، `ERROR` یا ❌ نشان داده می‌شوند.
   - چند ثانیه بعد از روشن شدن باید `telegram getUpdates works` بیاید. این یعنی ربات واقعاً پیام می‌گیرد.
   - اگر `getUpdates failed` یا `rejected` تکرار شد، اتصال تلگرام از روی کامپیوتر مشکل دارد. فیلترشکن را بررسی کنید.
   - `telegram polling stopped` همراه با 409 یعنی برنامهٔ دیگری با همین توکن پیام‌ها را می‌گیرد. پنجرهٔ دیگری از `npm run dev` یا هر برنامهٔ دیگر با این توکن را ببندید.
2. وقتی ربات روشن است، در **ترمینال دوم** بزنید:

   ```
   npm run dev:doctor
   ```

   این دستور چیزی را تغییر نمی‌دهد. نشان می‌دهد:
   - توکن مال کدام ربات است. مطمئن شوید به همان ربات پیام داده‌اید.
   - آیا webhook تنظیم شده است.
   - آیا پیامی در تلگرام منتظر مانده است.
   - آیا پیامی به ربات رسیده است.
   - آیا جوابی در صف ارسال گیر کرده یا با خطا رد شده است.

3. برای دیدن مسیر کامل هر پیام، در `.env` بگذارید `LOG_LEVEL=debug` و ربات را دوباره روشن کنید. برای یک `/start` درست، این خط‌ها به ترتیب می‌آیند:

   ```
   DEBUG telegram getUpdates {"count":1,...}
   DEBUG update received {"kinds":["message"],"events":["text"],"chat":"private",...}
   DEBUG command recognized {"command":"start",...}
   DEBUG replies queued in outbox {"outboxIds":[1]}
   DEBUG event handled {"outcome":"processed"}
   DEBUG outbox claimed {"ids":[1]}
   DEBUG outbox sent {"outboxId":1,"item":"send",...}
   ```

   هر جا زنجیره قطع شود، همان‌جا مشکل است:
   - نبودن `update received` یعنی پیام به این برنامه نرسیده است.
   - `event ignored` دلیلش را می‌گوید.
   - `send failed` خطای تلگرام را نشان می‌دهد.

4. خطای «اتصال به تلگرام برقرار نشد» یعنی توکن اشتباه است یا تلگرام از روی کامپیوتر در دسترس نیست. فیلترشکن را بررسی کنید.
5. اگر `/start` کار کرد ولی پیام «لولو» در گروه بی‌جواب ماند، Privacy Mode هنوز روشن است (گام ۱، مورد ۴).

## دادن پوینت برای تست

ارتقاها و خریدها پوینت زیادی لازم دارند. وقتی `npm run dev` روشن است، در **ترمینال دوم** بزنید:

```
npm run dev:grant -- @username_shoma 10000
```

به‌جای `@username` می‌توانید شناسهٔ عددی تلگرام را بدهید. آن حساب باید قبلاً یک بار به ربات پیام داده باشد. این دستور فقط روی دیتابیس توسعه کار می‌کند و در ledger و گزارش عملیات مدیر ثبت می‌شود.

# چک‌لیست تست دستی در گروه تستی

کنار هر مورد نتیجهٔ درست آمده است. موردهایی که «حساب دوم» دارند به حساب تلگرام دوم نیاز دارند.

### پایه

- [ ] `/start` در خصوصی: پیام خوش‌آمد و سه دکمه. دکمهٔ «غار من» پروفایل را نشان می‌دهد.
- [ ] `لولو` در گروه: پاداش ۱ تا ۱۰ پوینت.
- [ ] `لولو` دوباره: «لولوی بعدی … دیگر». تکرارهای بعدی تا یک دقیقه **بی‌جواب** می‌مانند تا گروه شلوغ نشود.
- [ ] جملهٔ «سلام لولو»: هیچ جوابی نمی‌آید.
- [ ] ویرایش یک پیام قبلی به «لولو»: هیچ پاداشی داده نمی‌شود.
- [ ] `لولوهام` و `غار من`: موجودی نقد، گنجینه و جمع.
- [ ] `لولو` در گفت‌وگوی خصوصی: پیام «این کار فقط داخل گروه انجام می‌شود».

### ارتقا و دکمه‌ها

- [ ] `ارتقای لولو` بدون پوینت کافی: پیام کمبود موجودی، **بدون** دکمهٔ تأیید.
- [ ] با `dev:grant` پوینت بدهید و دوباره `ارتقای لولو` بزنید، سپس «✅ تأیید»: سطح ۲ («اسکلت») و کم شدن هزینه.
- [ ] دوباره روی همان «تأیید» قدیمی بزنید: پیام «این دکمه قبلاً استفاده شده است».
- [ ] پیش‌نمایش بگیرید و ۲ دقیقه صبر کنید، بعد تأیید بزنید: پیام «مهلت این دکمه تمام شده».
- [ ] (حساب دوم) روی دکمهٔ تأیید حساب اول بزنید: پیام «این دکمه مال شما نیست».
- [ ] «✖️ لغو» بزنید و بعد تأیید همان پیام را: پیام «قبلاً استفاده شده».

### ابزار، شکار، غذا

- [ ] `ابزار شکار`، سپس «خرید چاقو» و تأیید: چاقو خریده و خودکار مجهز می‌شود.
- [ ] `شکار`: موفق یا ناموفق. تلاش دوباره: «شکار بعدی … دیگر» (یک ساعت).
- [ ] `سرداب`، سپس «خوردن …» و تأیید. بعد از ۵ دقیقه `لولو`: پاداش به‌صورت «پایه + غذا» نمایش داده می‌شود.

### قبرستان و گنجینه

- [ ] `قبرستون`، سپس «افتتاح قبرستان» و تأیید. چند دقیقه بعد `قبرستون`: موجودی نقد کمی بیشتر شده است.
- [ ] `واریز گنجینه ۱۰۰`، سپس تأیید و بعد `گنجینه`: موجودی گنجینه و زمان تا نیمه‌شب بعدی.
- [ ] `واریز گنجینه -5`، `واریز گنجینه 0` و `برداشت گنجینه ۱٫۲۳۴`: پیام خطای مناسب و بدون تغییر موجودی.

### انتقال (حساب دوم)

- [ ] حساب دوم یک بار `لولو` بزند. روی پیام او reply کنید و بنویسید `انتقال ۵۰`: پیش‌نمایش با نام و شناسهٔ گیرنده. تأیید کنید و موجودی هر دو را بررسی کنید.
- [ ] `انتقال ۵۰` بدون reply، یا reply به پیام خودتان یا پیام ربات: پیام راهنما و رد شدن انتقال.

### روح‌ها

بستهٔ روح **نمونه** (با برچسب [نمونه]) خودکار بارگذاری شده است.

- [ ] `جستجوی روح`: شانس ۳۰٪ است، پس ممکن است چند بار (هر ۳۰ دقیقه) طول بکشد. بعد از پیدا شدن، پیام روح با متن می‌آید.
- [ ] روی **همان پیام روح** reply کنید و `شنیدم` بنویسید: امتیاز ترس اضافه می‌شود. تکرار: «قبلاً شنیده‌اید».
- [ ] (حساب دوم) روی روح شما reply کند و `شنیدم` بنویسد: «این روح را کس دیگری پیدا کرده است».
- [ ] پیام روح را در همان گروه **فوروارد** کنید و روی نسخهٔ فورواردشده `شنیدم` بزنید: پاداشی داده نمی‌شود.
- [ ] `شنیدم` بدون reply: پیام راهنما.

### لولوآباد و ادمین

- [ ] `لولوآباد`، `بانک خون`، `شکارگاه` و `نفرین‌ها`: وضعیت پنج ستون شهر.
- [ ] `اهدای خون ۱۰۰`، سپس تأیید: موجودی بانک خون بیشتر می‌شود.
- [ ] (حساب دوم که ادمین نیست) `ارتقای آبادی`: پیام «فقط مالک یا ادمین‌ها».
- [ ] شما (سازندهٔ گروه) `ارتقای آبادی`: پیش‌نمایش. اگر جمعیت فعال کمتر از ۳ نفر باشد، پیام کمبود جمعیت می‌آید و این رفتار درست است.
- [ ] `ترسناک‌ترین لولوها`: رتبه‌بندی گروه و دکمهٔ «رتبه‌بندی جهانی».

### خاموش و روشن کردن

- [ ] با `Ctrl + C` خاموش و با `npm run dev` دوباره روشن کنید: موجودی و سطح‌ها همان است. اگر قبرستان دارید، درآمد زمانِ خاموشی هم واریز شده است.

### تست مهاجرت به supergroup (مهم)

این تست تأیید می‌کند که بعد از تبدیل گروه به سوپرگروه، شهر حفظ می‌شود و «شنیدم» کار می‌کند.

1. یک **گروه تازه** بسازید (گروه‌های تازهٔ کوچک معمولاً «گروه ساده» هستند) و ربات را به آن اضافه کنید.
2. چند بار `لولو` بزنید، `اهدای خون ۵۰` بدهید (با `dev:grant` پوینت بگیرید)، و `لولوآباد` را ببینید. موجودی بانک خون را یادداشت کنید.
3. `جستجوی روح` بزنید تا یک روح پیدا شود، ولی **شنیدم نزنید**.
4. گروه را به سوپرگروه تبدیل کنید. یکی از این دو کار را انجام دهید:
   - در تنظیمات گروه، «Chat history for new members» را روی **Visible** بگذارید.
   - یا نوع گروه را **Public** کنید (یک لینک عمومی بدهید).
5. **نتیجهٔ درست:**
   - در ترمینال: `group migrated to a supergroup; same city kept`.
   - در گروه: پیام «👻 روح شنیده‌نشدهٔ … (پیش از ارتقای گروه به سوپرگروه پیدا شده بود)».
   - `لولوآباد`: همان موجودی بانک خون و همان سطح؛ شهر جدیدی ساخته نشده است.
   - روی پیام **جدید** روح reply کنید و `شنیدم` بزنید: امتیاز ترس. تکرار: «قبلاً شنیده‌اید».
6. **برای گزارش به من:**
   - آیا تلگرام اجازه می‌دهد روی پیام روحِ **قبل از تبدیل** reply کنید؟
   - اگر بله، `شنیدم` روی آن چه جوابی داد؟

   این تنها رفتاری است که فقط با تلگرام واقعی قابل تأیید است.
